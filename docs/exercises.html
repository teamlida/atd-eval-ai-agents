Exercises

Hands-on exercises for the workshop. Each one builds on the last.

Before you start: finish Parts 0–2 of the setup guide (Python, the .venv, Google ADK and your Gemini API key in my_agent/.env). Run every command from the workshop folder, with (.venv) at the start of the prompt.

Stuck or behind? Every exercise starts from a branch with the finished code from the step before, so git checkout -f <branch> always gets you back on track.

The exercises

1 Talk to the agent, watch the tools
  • Branch agent-with-tool
  • Agent my_agent

my_agent has one tool, get_user_data(user_id), which fetches a user's profile from a mock API.

Set up

git checkout -f agent-with-tool
adk web --port 8000

Open http://localhost:8000 and pick my_agent in the top-left dropdown.

Do it

In one session, ask these three questions in this order:

  1. tell me the name of user 1
  2. tell me what is the favorite drink of user 1
  3. tell me what is the favorite drink of user 2

After each answer, click the events on the left of adk web. For every turn, note:

  • Did the agent call get_user_data? With which user_id?
  • What did the tool return, and does the answer match it?

Debrief

  • What did you see for each question?
  • What surprised you?
  • What would you want to test in this agent?
2 Write your first evals
  • Branch agent-with-tool or eval-agent
  • Agent my_agent

Now turn what you saw in Exercise 1 into evals for the first two questions. An eval replays a saved conversation against the agent and scores the result against criteria set in a config file.

Eval Question Criterion Checks
A · deterministic tell me the name of user 1 tool_trajectory_avg_score The agent called get_user_data with user_id = "1". Exact match, no judge.
B · non-deterministic tell me what is the favorite drink of user 1 rubric_based_final_response_quality_v1 An LLM judge checks that the answer contains the user's name.

1 · Record the conversations

  1. Start adk web --port 8000 and pick my_agent.
  2. Open the Eval tab and create an eval set, for example my_evals.
  3. Start a new session, ask question A, then click Add current session to my_evals.
  4. Start another new session, ask question B, and add it too.

ADK saves both cases to my_agent/my_evals.evalset.json. Open it in VS Code and find each case's eval_id, its final_response and its function_call entries.

⚠️ A recorded case expects exactly what the agent did that time. Check that the function_call in case A is really get_user_data with {"user_id": "1"}. If it isn't, fix it to what the agent should have called.

2 · Eval A: tool trajectory

Create my_agent/trajectory_config.json:

{ "criteria": { "tool_trajectory_avg_score": 1.0 } }

Run only case A by adding : and its eval_id to the file name:

adk eval my_agent my_agent/my_evals.evalset.json:<eval_id> --config_file_path my_agent/trajectory_config.json --print_detailed_results

3 · Eval B: rubric

Create my_agent/rubric_config.json:

{
  "criteria": {
    "rubric_based_final_response_quality_v1": {
      "threshold": 0.8,
      "judge_model_options": { "judge_model": "gemini-3.5-flash-lite", "num_samples": 1 },
      "rubrics": [
        {
          "rubric_id": "contains_user_name",
          "rubric_content": { "text_property": "The response contains the name of the user." }
        }
      ]
    }
  }
}
adk eval my_agent my_agent/my_evals.evalset.json:<eval_id> --config_file_path my_agent/rubric_config.json --print_detailed_results

Behind or stuck? git checkout -f eval-agent has a finished eval set (my_agent/eval_set_1.evalset.json) and config (my_agent/test_config.json).

Debrief

  • What did your evals show?
  • What surprised you?
  • When would you use a deterministic check, and when an LLM judge?
3 Bug hunt at The Unicorn & Parrot 🍺
  • Branch challenge
  • Agent beer_agent

The Unicorn & Parrot is a pub in Potsdam. Its bartender, Polly the parrot, is a chatbot that answers questions about drinks and takes orders. Polly has bugs.

1 · Explore the oracle

Start with the pub's page: teamlida.github.io/atd-eval-ai-agents. It has the menu, the house rules, the register's tools, and a register you can try yourself.

The page is the oracle. It is always right. Whenever Polly says or does something that doesn't match the page, you've found a bug.

2 · Switch to the challenge branch

git checkout -f challenge

Give Polly your API key by copying the .env you made for my_agent:

cp my_agent/.env beer_agent/.env

On Windows (PowerShell): Copy-Item my_agent\.env beer_agent\.env

Start adk web --port 8000 and pick beer_agent in the dropdown.

3 · Hunt

Chat with Polly and compare what it says and does with the page. The events on the left of adk web show which tools Polly called, with which inputs, and what the register answered.

4 · Prove it with evals

Find at least 4 bugs and cover each one with an eval that fails:

  • 2 deterministic evals: tool_trajectory_avg_score or response_match_score.
  • 2 non-deterministic evals: rubric_based_final_response_quality_v1, with a house rule in your own words as the rubric.

Use the same workflow as Exercise 2, with beer_agent in place of my_agent. After recording a case, correct its expectation to what Polly should have done.

adk eval beer_agent beer_agent/test.evalset.json:<eval_id> --config_file_path beer_agent/trajectory_config.json --print_detailed_results

An eval that catches a bug fails. That's the goal.

💡 Free API keys allow about 15 requests per minute. If you hit 429, wait a minute: that's a quota, not a bug.

The step-by-step version, with config templates, is in the README on the challenge branch.

Debrief

  • Which bugs did you find, and which kind of eval caught each one?
  • Which bugs were hard to turn into an eval? Why?
  • What surprised you?
  • What would you put in a regression suite for Polly?
